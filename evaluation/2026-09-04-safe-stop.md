# Safe-stop decision record

Date: 2026-09-04  
Status: Dry-run and graceful disposable-fixture acceptance passing; force stop absent

## Implemented boundary

`port-tools stop <service-id> --dry-run` resolves the service from a fresh scan,
then creates a human-readable or JSON stop plan. The command never calls
`kill(2)` and its output always includes `signalSent: false`.

`port-tools stop <service-id> --graceful` is a separate explicit action. It
builds the plan twice, refuses changed identity or scope, sends `SIGTERM` to the
approved PIDs, and reports success only after every expected address and port
has no listener. Invoking `stop` without either explicit mode is rejected before
a service scan is performed.

## Eligibility policy

A target is eligible for a future graceful stop only when all of these are true:

- the scanned owner and current PID owner are the current macOS user;
- the PID still exists and its start time and command match the fresh scan;
- a single Git project establishes application ownership;
- the target is not a Docker-published service or recognized shared/system runtime.

The listener PID is the root of the current prototype's stop scope. Descendants
are direct-signal candidates only when their current owner and Git project match
the root. Other-user, cross-project, and unverified descendants are listed as
exclusions. The proposed order is deepest eligible descendants first, then the
root PID, using `SIGTERM` only. `SIGKILL` is explicitly unavailable in this
action and requires a separate future action and confirmation.

## Evidence

The unit suite passes 25 tests, including dedicated cases for nested process
trees, other-user refusal, Docker refusal, unattributed/shared-runtime refusal,
cross-project descendant exclusion, listener verification targets, and reused
PID identity rejection.

A live read-only run against a current-user Vite service produced an eligible
plan for exactly its listener PID and `127.0.0.1:4317`. The plan reported
`signalSent: false` and `forceAllowed: false`. A subsequent `lsof` check showed
the same PID still listening on the same port. No process was started, stopped,
or signalled during this validation.

The authorized termination test then created exactly two disposable fixtures:
a static HTTP service on `127.0.0.1:51739` and a shell-wrapper/child service on
`127.0.0.1:51743`. Both were identified as current-user processes owned by this
repository. Each explicit graceful action sent `SIGTERM` to exactly the approved
listener PID and confirmed its port was released. Stopping the first fixture did
not interrupt the second. Both fixture parent processes exited, all test ports
were released, and runtime artifacts were removed. No `SIGKILL` occurred.

## Deliberately unproven

- wrapper-process ownership above the listener PID;
- force-stop behavior;
- Docker container stop behavior.

The timeout result path is implemented but has not been tested with a deliberately
uncooperative process because that cleanup would require a separately authorized
force action. The production UI must preserve the same two-action boundary.

## Packaging impact

The JSON structures in this spike are an internal contract for a future daemon
and menu-bar UI. The Python implementation is not intended to ship. Production
process inspection and signalling must live in a bundled native executable, and
fixture code, fixture dependencies, test certificates, and test state must never
be included in the release payload.
